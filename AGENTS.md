## Verification
Verify all changes: `npm run check:all`. Changes to grants, the scraper or anything that reads catalog records also need `npm run check:live`: it builds the catalog the in-app sync produces (network, about a minute) and checks the rules against it, which the tracked snapshot cannot do. UI changes also need `npm run layout:check` (it starts its own Expo web server; add `-- --integrated` for the integrated catalog; first run needs `npx playwright install chromium`); layout rules are in `CODING_STANDARDS.md` section 7.

## Subagents
- Implementer rules (Git, worktree setup, data folders, baselines): `docs/agents/subagent-tiering.md`, section "Implementer Rules".

## Compendium Architecture
- SRD baseline: `src/data/*.json` (pruned via `node scripts/prune-to-srd.mjs`). Do not overwrite with expansion content.
- Integrated compendium: generated by `dnd5eToolsScrap/` and cached via `src/services/compendiumStorage.ts`.

## Navigation
- Progression & spells: `src/rules/` (`spellcasting.ts`, `ruleChoices.ts`, `characterEvaluation.ts`).
- Combat economy & actions: `src/rules/` (`attacks.ts`, `ac.ts`, `tacticalActions.ts`).
- In-app scraper & cache: `src/services/scraper/runner.ts`, `src/services/compendiumStorage.ts`.
- Proficiencies: `src/rules/proficiencySheet.ts` is the one reader; its private sources live in `src/rules/proficiencySources/`. `checks/proficiencyReadersGuard.test.ts` enforces it.
- UI: character tabs in `src/components/tabs/`, builder sections in `src/components/builder/`, shared UI components in `src/components/ui/`, the character header in `src/app/character/[id].tsx`, and modals in `src/components/` (`*Modal.tsx`) with the shared shell `src/components/ui/Modal.tsx`.
- Character test fixtures: `makeChar()` in `checks/testUtils.ts`.
- Architecture decisions: `docs/adr/`.
