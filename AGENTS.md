## Verification
Verify all changes: `npm run check:all`. Changes to grants, the scraper or anything that reads catalog records also need `npm run check:live`: it builds the catalog the in-app sync produces (network, about a minute) and checks the rules against it, which the tracked snapshot cannot do. UI changes also need `npm run layout:check` (it starts its own Expo web server and runs the five widths 320, 360, 393, 412 and 768 in parallel — 768 is the tablet breakpoint, so the builder and flow wide layouts at 768px are gated too — about 12 minutes for the SRD Baseline and about 14 minutes with `-- --integrated` (measured 12m07s and 14m15s; each width alone takes 8-14 minutes, the widths run at the same time); `ONLY=<name>` visits only the scenarios whose name contains it; first run needs `npx playwright install chromium`); any UI change touching the flow shell (wide footer, identity side column from 1024px up, step list) also needs `WIDTHS=1024,1280 npm run layout:check`, as do the other wide layouts (sheet rail, Home grid) — the default run stops at 768 on purpose: a measured six-width default that also ran 1024 took 13m07s and peaked at 11410 MiB (about 11.1 GiB) used memory, over the roughly 11 GB a 14 GB machine can spare; all times were measured on an 8-core, 14 GB machine; layout rules are in `CODING_STANDARDS.md` section 7. A native-only change (inputs, `Platform.OS` branches, Android-only styles, text clipping) also needs `npm run layout:android` with `ONLY` set to the scenarios that show the change: it costs minutes, needs the generated `android/` project and the Android SDK, and is documented in `docs/agents/driving-the-android-emulator.md`.

## Compendium Architecture
- SRD baseline: `src/data/*.json` (pruned via `node scripts/prune-to-srd.mjs`). Do not overwrite with expansion content.
- Integrated compendium: generated by `dnd5eToolsScrap/` and cached via `src/services/compendiumStorage.ts`.
- "Nothing hard-coded" means no non-SRD content in `src/`: no rule text, option names, tables or lists from a non-SRD book (ADR 0014). A rule a non-SRD book defines reaches the app as Catalog data the scraper builds from the book's own record (for example `data/variantrules.json`). Structure, numbers and SRD rules may live in code, in a named module.
