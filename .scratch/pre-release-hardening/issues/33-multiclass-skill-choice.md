# 33: A later class's multiclass skill choice is offered and counted

**What to build:** Owner bug report. A Knowledge Cleric who takes a level of Rogue is never offered the one skill from the Rogue list that the multiclass rule grants (Ranger and Bard have the same rule). The catalog already carries it: `multiclassing.proficienciesGained.skills` on the class record (a "choose N from" with the list; Bard's list is every skill). `addMulticlassLevel` (`src/rules/builderTransitions.ts`) writes a `multiclass_skill_<class>` entry into `character.skillChoices` with nothing picked, but nothing reads it: `skillChoiceOffers` (`src/rules/proficiencySheet.ts`) only returns the first class's choice, so no picker is drawn and no pick can reach the sheet.

**Blocked by:** None (can start immediately)

**Status:** done

**Landed:** merged from `pr/33-multiclass-skill-choice` (9899da2). `check:all` passes on the merged tip (1197 app tests, 7 skipped, 178 scraper tests); `check:live` 53 of 53 on the branch. `multiclassSkillGrantOf(cls)` in `src/rules/proficiencySources/classBase.ts` builds the choice grant from the class record; `featuresOf` adds a `Multiclass Proficiencies` feature per later class entry; the picker is titled `<Class> multiclass: Skill`; grant id `<source>/<Class>/Multiclass Proficiencies@1#skills:choice:from` (`:any` when the record names no list). The pick is released when its class is removed or becomes the first class. `dropLegacyMulticlassSkillEntries` (run by the reconciler) drops empty `multiclass_skill_*` entries from old saves. Live catalog, one Rogue/Ranger/Bard later class: Rogue 11 options, Ranger 8, Bard 18, Monk and Wizard none. Open items: the first class's skill picker still reads `ruleGrantedSkills`, which leaves out class-origin features, so a skill taken as a multiclass pick can still be offered there (ticket 35 closes it); a later class from a turned-off book loses its pick on the sheet while the book is off and the pick is kept; `removeClassLevel` keeps a dead `multiclass_skill_` branch; no layout check, no UI code.

## Design notes

- Make the multiclass skill choice a **Proficiency Choice** (GLOSSARY), like every other pickable grant, and not another `skillChoices` bucket. The sheet already builds a feature for the first class's starting proficiencies (`startingFeatureOf` in `src/rules/proficiencySheet.ts`); add the same kind of feature for each later class entry whose record has a skill choice, carrying one choice grant (category `skills`, count and pool from the record). The existing offers machinery (`proficiencyChoiceOffers`, `ProficiencyChoicePicker`) then draws the picker in the Class card, the pick is stored in `character.proficiencyPicks` under the grant id, the sheet reads it through `choicePickNames`, and the pick is released when the class entry goes away (the existing `pruneInvalidProficiencyPicks`).
- The grant id is derived from what the grant is, never from a position (`docs/adr/0015-proficiency-grants-live-in-the-catalog.md`): category, kind and the class's name and source, for example `<source>/<Class>/Multiclass Proficiencies@#skills:choice`. Do not put the pool or count in it. `checks/fixtures/proficiencyGrantIds.json` pins shipped ids: add the new ids through its recorder if the check demands them, and say so in the report.
- The picker title must name the class ("Rogue multiclass: Skill"). `pickerTitles` builds titles from the feature name, so name the feature after the class or add the class to the title; keep one title per class when two later classes both offer a skill.
- The pool is the record's list less the skills the character holds from other sources, with the choice's own pick kept (`heldByOtherSources` already does this for every other choice). The first class never gets this choice: the multiclass skill is for a class taken after the first.
- The data stays in the catalog: no class names, no skill lists in app code. A class record with no `proficienciesGained.skills` offers nothing; a class with no `multiclassing` record cannot be taken later (existing behaviour).
- Remove the dead write: `addMulticlassLevel` stops creating the `multiclass_skill_<class>` `skillChoices` entry. Saves that hold one load with it dropped by the existing load-time migrations path (put the removal next to the other `move...` migrations in `src/rules/proficiencyPicks.ts`, called where those are called); such an entry can only be empty, because nothing could pick into it. Keep the `multiclassProficiencies` record (armor, weapons, tools) as it is.
- Test first at the sheet seam with an invented class record that has a multiclass skill choice: a character with two classes is offered the pick, the pick lands in `proficiencySheet(...).skills`, a held skill is not offered, removing the class releases the pick, the first class is not offered it. One test over the SRD baseline: Rogue, Ranger and Bard each offer one pick as a later class and no other SRD class does. One test that an old save holding an empty `multiclass_skill_rogue` entry loads clean.

## Acceptance criteria

- [ ] A character who adds Rogue, Ranger or Bard as a later class is offered the multiclass skill pick in the Class card, and the pick appears on the Proficiency Sheet and the skills list.
- [ ] A skill already held is not offered, and the pick is released when the class entry is removed.
- [ ] `multiclass_skill_*` entries are no longer written; old saves holding one load.
- [ ] The offer comes from the catalog record: no class name or skill list is added to app code.
- [ ] `npm run check:all` passes.
